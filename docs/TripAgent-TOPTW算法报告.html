1 · 一页看懂

TOPTW（Team Orienteering Problem with Time Windows，带时间窗的团队定向问题）回答的是：时间预算有限时，去哪些点、按什么顺序去，能让行程总价值最大。它与 TSP/VRP 的本质区别在于——TSP/VRP 要求访问全部节点、最小化成本；TOPTW 允许放弃部分节点（损失其利润），在时间预算内最大化选中节点的利润总和。这恰好就是行程规划的核心权衡：景点无穷多，一天只够去三四个。

TripAgent 用 OR-Tools RoutingModel 把「一天行程」建模成单车 TOPTW：利润函数编码「主选权重 + 景点评分 + LLM 顺位奖励」，硬约束（营业时间窗、通行时间、当日上限）由求解器保证可行，软约束（建议游玩时段）以罚分形式参与优化。求解器有权把 LLM 提案里时间上放不下的点换掉——这是整个系统「世界知识提案 + 求解器守门」双引擎结构的第二台引擎。

2 · TOPTW 问题原理

2.1 从定向越野说起

OP（Orienteering Problem）的名字来自定向越野：选手从起点出发、在关门时间前到达终点，途中经过若干检查点各得相应分数，如何选点与排序使得分最大。形式化定义：

N 个候选点，每点利润 Sᵢ、访问耗时 Tᵢ、时间窗 [eᵢ, lᵢ]
通行时间矩阵 C(i,j)
总预算 Tmax
max  Σ Sᵢ·xᵢ            （选中点的利润和）
s.t. 路径连通、连续；
     到达时刻 + Tᵢ ≤ 离开时刻，且落在 [eᵢ, lᵢ] 内
     总时长 ≤ Tmax

加「团队」（多辆车，K 条路径）即为 TOP；再加时间窗即为 TOPTW。该问题是 NP-hard 的——精确算法只适用于几十个点的规模，实用系统普遍采用构造启发式 + 元启发式改进。

2.2 与相邻问题的对照

问题目标节点访问时间窗典型解法
TSP最小化路径成本全部必访无2-opt / Concorde 精确
VRP最小化总成本全部必访可选（VRPTW）列生成 / 大邻域搜索
TOP / TOPTW最大化选中利润可选（弃点损失利润）TOPTW 必有构造 + GLS / 模拟退火

3 · 求解技术：OR-Tools 建模三要素

本项目使用 Google OR-Tools 的 RoutingModel（CP-SAT 系约束求解），三个关键机制分别对应 TOPTW 的三个组成部分：

机制API在本项目中的用法
可选访问AddDisjunction([idx], penalty)每个候选点挂一个 disjunction；penalty = 该点利润——求解器访问它就赚利润、跳过它就损失利润，penalty 与绕路成本自动权衡。这是「选点」能力的来源
时间维度AddDimension(transit_cb, 0, horizon, fix_start=False, "time")transit 回调 = 上游游玩时长 + 通行分钟；节点 CumulVar 设硬范围 [开门, 闭店−游玩时长]（到达截止语义与 sequencer 对齐）；horizon = 当日跨度 − 120min 餐块缓冲
软时间窗SetCumulVarSoftLowerBound / SoftUpperBoundbest_time 建议时段（morning/afternoon/evening/lunch）映射为软窗，偏差每分钟罚 5 分，并有 60 分钟封顶（见 §5）
实现细节：自环（未被访问的可选节点）transit 必须返回 0，否则时间维度不可行——这是 OR-Tools 建模的经典坑；另RoutingIndexManager 的绑定参数顺序为 (num_nodes, num_vehicles, starts, ends)，传错会静默得到错误规模。

4 · 利润函数：把「产品语义」编码进目标

TOPTW 的落地质量几乎取决于利润函数怎么设计——它决定了求解器「认为什么重要」。TripAgent 的利润分四层：

profit(p) = 60 × rating            ← 平台评分（3~5 分制）
          + 15 × rank              ← LLM 提案顺位（首点 rank 最大，逐位递减）
          + 600 × 主选标记          ← LLM 主选一次性加成
          + 1,000,000 × 必选标记    ← forced（住宿锚点地标），不可舍弃

典型利润构成对比（rating=4 主选 vs 备选 vs 必选锚点）

设计点取值理由
MAIN_BONUS600M3-1 参数扫描 300~1000 结果一致，取中位留余量——保证「任何一个主选 > 任何几个备选之和」，求解器只会在时间不可行时才动主选
RATING_W60/分同分主选之间按评分定去留；两档评分差 120 分 < 600，不会翻越主选边界
RANK_BONUS15/名同为主选时保持 LLM 顺序（相似度目标）；参照 Google 可配置行程生成论文的同型设计，该论文中「与用户需求相似度」占利润 70% 权重
forced+10⁶住宿锚点等地标必选点；舍弃代价远超任何组合收益，但时间可行性仍由硬窗保证——必选点排不下会暴露为违规而非被静默丢弃

5 · 时间约束体系：硬窗、软窗与封顶

这是本项目迭代最多的部分，共四层，由硬到软：

层机制语义
① 当日域horizon = 当日跨度 − 120min排序器会在日中插午餐+晚餐各 1h，求解预算预扣餐块缓冲（M6），防止过度打包后整体后移溢出
② 营业硬窗CumulVar.SetRange(开门, 闭店−时长)到达 + 游玩 ≤ 闭店；窗口为空的点（闭店前玩不完）在建模前预剔除，防 CP Solver 直接 fail
③ 建议软窗SoftLowerBound / SoftUpperBound，5 分/分钟morning→12 点前、afternoon→13 点后、evening→17 点后、lunch→11~13:30（SLOT_WINDOWS）
④ 软窗封顶偏差 >60min 收紧硬域M3-2 关键修正：旧逻辑线性罚分无上限（晚到 5h 罚 1500 分），求解器「宁可晚到硬扛罚分」也不弃点——morning 点被拖到傍晚、时段空间白扔；封顶后要么贴时段排、要么干脆不排（弃利润），腾出的空窗由日内填空补 evening 型点
冲突仲裁：软窗封顶与营业窗冲突时营业窗优先（能开就行）——约束的优先级是 硬可行性 > 时段偏好 > 利润。

6 · 求解器配置与提前停止

p.first_solution_strategy   = PATH_CHEAPEST_ARC      // 构造：最便宜弧优先
p.local_search_metaheuristic = GUIDED_LOCAL_SEARCH    // 改进：引导局部搜索
p.time_limit                = 2.0s                    // 单日预算

GLS 在搜索末段常出现「解略有提升但耗时照付」的空转——实测 2s 预算 100% 打满。项目挂了 at-solution 回调做收敛判断：

每次求得新解 → 记录 CostVar().Max()
连续两次提升 < 0.5% → solver.FinishCurrentSearch() 提前结束
（SolveWithParameters 仍返回当前最优解；回调取值失败则等 2s 超时兜底）

提前停止效果（实测，武汉 2 日 + 杭州 2 日多组样本）

求解失败（sol is None）时返回 solved=False，上层自动降级 M1 贪婪链路——求解器不可行不会导致整单失败，这是三级降级链（M7 求解 → M2 兜底 → M1 贪婪）的入口之一。

7 · 编排层：TOPTW 在整条管线里的位置

单日求解器之上是 _solve_all_days 编排层，四项工程化设计：

设计实现收益
逐日建池主选 + LLM alternates（同天优先）+ 地理邻近召回，全局 used_backup 去重池约 45 点/天：够求解器换点，又不至于稀释利润信号
线程并行建池串行（维护去重状态）→ 线程池并行求解（≤4 并发）→ 串行合并OR-Tools 求解释放 GIL，多天耗时 ≈ 最慢单天
天复用（reuse）C 闭环/重平衡未触及的天直接复用上次有序解，不重解跨天调整只动少数天，全量重解是纯浪费
闭馆预剔除日期感知：当日闭馆的主选进池前剔除并记「求解器强制换点」主选闭馆信号进闭环 REVISE，而非求解器内部静默换点
酒店 depothotel 作为虚拟节点（全天开放、0 时长）置于 nodes[0]，每日强制出发返回首尾交通真实；无酒店时用「首主选换位到 depot」替代

求解输出两样东西：有序访问序列（交给 sequencer 做时间轴与修复链）和被弃点列表（进入「为什么没去这些点」的用户可见解释 + 闭环信号）。被剔主选会触发两级补救：提案备选确定性补位（同主题优先）→ LLM 兜底补点；需求主题（动物/博物馆等）彻底丢失时向用户出 ⚠️ 通知。

10 · 边界与演进方向

  • 单车模型：单日单路径符合旅游场景；若引入「上午/下午分组」需求，可扩展为 2 车 TOPTW（ morning 组 + afternoon 组）。
  • 利润静态性：利润不随拥挤度/天气变化——拥堵与天气感知排入待办后，可作为时段相关的利润调整项注入。
  • 预算感知：门票价格未进目标函数，可加预算约束维度（预算内利润最大化）。
  • 提前停止阈值：0.5%/连续两次为经验值，可在更多城市样本上校准（当前单日 0.2~1.1s 已接近建池固定开销）。
