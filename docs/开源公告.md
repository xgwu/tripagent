## 一句话介绍

**TripAgent** 是一个 LLM 世界知识 × OR-Tools TOPTW 的混合行程规划系统：
大模型决定「去哪、为什么去」，本地结构化 POI 库 + 运筹优化保证行程**物理可行、结构最优**——
真实路网时间、营业窗口、闭馆日、餐窗、里程预算，一个都不少。

12 座中国城市、722 个人工策展 POI、46,575 对真实路网交通缓存，端到端 12.9 秒出一份可执行的每日行程（含时间轴、地图、文案、日历导出）。

## 为什么不是「让 GPT 写攻略」

直接让大模型生成行程，会踩四个结构性坑：**地点幻觉、营业时间冲突、跨天重复、里程不现实**。
TripAgent 的答案是把「品味」和「可行性」拆给两个世界：

```
需求文本 → 多轮澄清
        → A·世界知识提案（LLM：主选 + 理由 + 备选，prompt 规则按需注入）
        → B·落地匹配（四级回库：精确 → 变体 → 模糊 → LLM 辅助；未落地 = 库缺口采购清单）
        → C·TOPTW 求解（OR-Tools：硬时间窗 + 忠实模式——选点权归提案，求解器只排序保可行）
        → D·闭环与文案（跨天重平衡 → 净零换位 → 缺口回传修正 ≤2 轮 → 文案对齐最终时间轴）
```

防幻觉不靠限制提案，而靠**落地匹配 + 反馈闭环**：落地率 <85% 自动带原因重提案；
未落地的点名沉淀为「POI 库缺口台账」，反向驱动 12 城库持续扩容——这套循环我们真实跑了 18 个里程碑。

## 亮点

- 🏙 **12 城 722 POI**：沪/京/穗/蓉/杭/宁/汉/苏/西安/重庆/长沙/盐城，每点含坐标、营业时段（含跨零点归一化）、适玩时长、实拍图
- 🧮 **硬约束求解**：营业硬窗 + 酒店锚点 + 餐窗保障 + 主题里程预算（骑行/徒步/自驾）+ 远郊大点片区守门
- 🔁 **忠实执行模式**：TOPTW 只做排序与可行性，选点权收归提案层——杜绝「求解器悄悄换掉你点名要去的地方」
- 🚗 **城际转移段**：跨城联游自动生成转移日 / 夜间转移 / 抵达日顺延，驾车时长三级模型（缓存 → 高德 → 直线兜底）
- 🛡 **全链路降级**：LLM 挂 → 离线规则引擎；ortools 缺 → 贪婪排序；地图挂 → SVG 手绘图。**服务永不中断**
- 📊 **可复现质量**：18 例固化回归 + 12 城库校验，一条命令发布门禁（CI 同款）

## 快速开始

```bash
git clone https://github.com/xgwu/tripagent.git
cd tripagent
pip install -r requirements.txt      # 唯一可选第三方依赖为 ortools
cp secrets.json.example secrets.json # 填入高德 + DeepSeek key
python webui/server.py 8765
# 打开 http://127.0.0.1:8765
```
