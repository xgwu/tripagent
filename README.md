# TripAgent 🧭

LLM 世界知识 × OR-Tools TOPTW 混合行程规划系统 —— **世界知识主导选点，确定性系统负责落地 + 约束 + 求解**。

通用大模型的旅行「品味」很好，但直接生成的行程不可行：地点幻觉、营业时间冲突、跨天重复、里程不现实。TripAgent 让 LLM 凭世界知识决定「去哪、为什么去」，本地结构化 POI 库 + 运筹优化保证行程**物理可行**（真实路网时间、营业窗口、闭馆日、餐窗、里程预算）且**结构最优**（TOPTW 排序与可行性）。防幻觉不靠限制提案，而靠落地匹配——未落地的提案自动成为「POI 库缺口采购清单」，反向驱动数据扩容。LLM 不可用时全链路确定性降级，服务永不中断。

## 核心链路（M7 经验提案 + M11 忠实执行）

```
需求文本 → 0·目的地解析（受支持城市/景区直接命中；说**省份/区域**如「贵州5日自驾」→ LLM 从 31 个受支持目的地里挑有序子集，受 POI 库硬约束；解析不出**明确报错**，绝不静默回落默认城市）
        → 0.5·多轮澄清（LLM 保守判断需求缺失，至多追问一问，选项卡片交互）
        → A·世界知识提案（LLM 自由生成多日行程：主选 + note + alternates + 招牌/片区/餐窗规则，prompt v10 常开硬规则+条件规则按需注入）
        → B·落地匹配（四级回库：精确 → 分支变体 → 包含/模糊 difflib≥0.62 → LLM 辅助；失败记入库缺口台账）
        → C·TOPTW 求解（OR-Tools 逐日：营业时间窗 + 酒店锚点 + 闭馆硬过滤；忠实模式池=主选，只排序）
        → D·闭环与文案（跨天重平衡 → alt 净零换位 → 缺口/剔除回传 LLM 修正 ≤2 轮 → 文案对齐最终时间轴）
```

**四层防护**保证产出质量：

- **提案层**（prompt v10：**常开硬规则 + 条件规则按需注入**）：7 条常开硬规则（全天大点独占日、远郊大点片区、跨天片区分散、配套顺路、正餐、备选、远郊深度体验）始终注入；6 条条件规则仅在判据命中时注入（招牌体验/亲子/慢节奏/贯穿偏好/住宿锚点/点名）。v9 把 14 条规则全量堆进 prompt 且靠散文声明优先级（贯穿偏好覆盖片区分散、慢节奏豁免傍晚密度），v10 让冲突从根源消失——慢节奏命中时傍晚密度规则根本不进 prompt。判据复用 `sequencer` 现成正则，普通查询 prompt 2849→1567 字符
- **守门层**：远郊大点片区守门——距市中心 >12km 的 4h+ 大点与 10km 外片区错配混排时，求解前自动重排到最近的天；family 严格档下 5h+ 远郊点独占一日；**环湖/海岛主题日豁免不拆**；跨天片区分散（相邻两天 <1.2km 点位对触发闭环）
- **求解层**：**忠实执行模式**（默认开）——池=主选、主选以 10⁶ 利润锁定、落地 ≤ 提案、剔除原因单一；可回退为「主选高利润 + 双源备选换点」
- **闭环层**：落地缺口 / 落地率<85% / 主选被剔 ≥2 处 → 带原因回传修正再求解（≤2 轮防震荡）；备选补位**净零换位**（同主题优先）；需求标签（动物/博物馆等 16 类白名单）点位被剔光且无同主题保留 → 前端 ⚠️ 明确通知，而非静默丢失

降级路径：LLM 不可用 → 离线规则引擎；ortools 缺失 → 贪婪排序；高德不可用 → SVG 手绘图 + 直线折线；天气/节假日接口失败 → 静默跳过。

## 功能特性

- **31 城 1193 POI**（贵阳/广州各 79 / 成都/苏州各 75 / 北京 74 / 上海 69 / 杭州 57 / 西安 54 / 武汉 50 / 南京 49 / 重庆 48 / 长沙 47 / 盐城 45 / 兴义 43 / 遵义 34 / 万峰林 33 / 安顺 32 / 六盘水、凯里各 31 / 黄果树 29 / 铜仁 21 / 都匀、镇远古城各 20 / 小七孔、梵净山、西江千户苗寨、中国天眼各 16 / 赤水 11 / 织金洞 9 / 肇兴侗寨 8 / 百里杜鹃 6），62,793 对真实路网交通缓存（L1 OSRM + L2 高德实况，L3 直线兜底），库内点位实拍图 **1174/1193 = 98.4% 覆盖**
- **区域/省份级需求**（2026-09-21）：说「贵州5日自驾游」「江南水乡5日游」也能规划——前置解析用 LLM 从 31 个受支持目的地里挑有序子集（受 POI 库硬约束，不会排没库的城市），再交给既有的跨城链路（转移段/自驾主题）。LLM 不可用时按省份机械展开**并显式告知**（降级 notice）；**解析不出就明确报错，绝不静默回落默认城市**——实测「川西4日游」原会被静默排成上海（还标 `from_query=true`）
- **硬约束体系**：营业时间、闭馆日（日期感知，全库回填）、**跨零点闭店归一化**、餐窗美食（每窗 ≤1，咖啡馆非正餐分流）、返程酒店锚点、主题每日里程预算（骑行/徒步/自驾）
- **节奏档**：慢节奏（老人/轮椅/行动不便/不要太累）全链路宽松化——2–3 点/天、白天为主、真夜间点全清、站数下限 3；傍晚空窗自然留白（不自动补点）
- **餐窗保障**：正餐 POI 优先占窗、到达距饭点 ≤30min 先吃再逛、游完就地补餐、窗尾宽限与收尾晚餐提前量、**餐窗提前容差**（餐厅不必干等到 12:00/18:00 整点）+ **日内空档逐日披露**（求解器不惩罚空档，至少不静默）
- **贯穿性偏好**：「最好临湖」「环湖骑行」类需求穿透全链路（判据 + prompt 规则 + 湖线点利润加成 + 剔点/补位/补天三处保主题）
- **远郊守门 + 主题保真**：几何合理性事前保证（而非修复链事后剔点误杀主选）；补位同主题优先 + 需求丢失显式通知
- **点名与远郊召回**：用户点名的库内点位**确定性注入**（不依赖 LLM 是否采纳）+ 必选对账（排不进则显式告知）+ **目的地型餐饮豁免**（农家乐/湖鲜馆不被当作绕路配套剔除）+ 夜间点求解预算放宽（19:00 开门的点位可入选）
- **多轮澄清**：需求缺失时保守追问一轮（选项卡片），已与需求抽取合并为单次 LLM 调用
- **跨城联游**：「苏杭 4 天」自动识别跨城，逐城规划合并 + 住宿城市天数倾斜；**每城天数尊重用户明说的诉求**（「苏州玩2天」按确定性正则解析，不再 divmod 盲分）
- **城际转移段**（`src/intercity.py`）：跨城驾车时长走三级模型（磁盘缓存 → 高德 driving → 直线×1.25÷75km/h 兜底，**不能复用 `travel_hours`**——它的市内速度模型会把苏州→杭州算成 9.6h）。≥4h 独占转移日（>10h 按单日上限拆多天）、<4h 顺延抵达日起始时刻、「晚上9点开车去苏州」识别为夜间转移挂在出发城当天末尾；转移段在时间轴与地图上均可见。**跨城交通方式只认用户明说的**（自驾/高铁/飞机）——没说就不假定自驾：转移行显示「X → Y（城际交通待定）」且 `mode=null`，时长仍按驾车口径估算**并如实披露口径**，以后用户指定高铁/飞机时按需填补
- **自驾主题**：`自驾/租车/驾车` 命中 driving 画像（每日 400km 预算，作用于含城际段的天），hop 标签显示「自驾」
- **性能工程**：天复用增量重解 + TOPTW 线程池并行 + at-solution 提前停止 + 提案级缓存（7 天 TTL）——端到端 23.3s → 首次 12.9s / 缓存命中 8.3s，质量零回归
- **天气/节假日感知**：open-meteo 免 key，≥60% 降水提示室内 + 备雨具
- **高德地图**：真实底图 + 按日着色 marker + 骑行/步行实际路网折线 + POI 静态图缩略
- **反馈闭环**：日卡「🔁 换一个」—— 同主题邻近换点并重排当天时间轴（确定性补位优先）
- **分享与导出**：行程快照短链 `?share=<id>`、PNG 长图 / ICS 日历导出、行程单打印/存 PDF
- **五段式进度条**：澄清→提案→落地→求解→文案分阶段轮询，等待可感知
- **公开护栏**：滑动窗口限流（8 次/300s/IP）、统计埋点、`/api/cities` 不回传服务端 Key

## 快速开始

```bash
# 1. 依赖（唯一可选第三方依赖为 ortools）
pip install -r requirements.txt

# 2. 配置密钥：复制 secrets.json.example 为 secrets.json 并填入真实值（secrets.json 不进 git）
#    deepseek_api_key / amap_key（Web 服务）/ amap_js_key（前端 JSAPI）
#    业务配置（模型名、功能开关等）放 config.json，随 git 提交
#    开关：anchor_hard_guarantee（住宿锚点硬保障，默认 false）/ toptw_faithful_mode（忠实执行，默认 true）

# 3. 启动（默认 8765；云端读 PORT 环境变量并绑 0.0.0.0）
python webui/server.py 8765

# 4. 打开 http://127.0.0.1:8765
```

> 首跑说明：`travel_cache.json`（路网时长矩阵）与 `photo_cache.json`（实拍图）
> 不随仓库分发。缺失时全链路自动降级（L3 直线兜底 / 图片回退瓦片），服务正常；
> 需要完整精度可按需重建：`python scripts/build_travel_cache.py <城市>` 与
> `python scripts/backfill_poi_photos.py <城市>`（需自备高德 key，构建结果仅本地生效）。

CLI 单次规划（注意：CLI 从环境变量读密钥，`webui/server.py` 会自动注入 secrets.json）：

```bash
python main.py "带5岁孩子去杭州玩2天，不要太累，最好有动物或者博物馆" --city 杭州 --days 2 --proposal --date 2026-10-01
```

| `/api/plan` | GET | 规划：`city/query/date/hotel/llm`；天数从 query 提取（1–5，默认 2）；查询含 ≥2 城自动跨城；**支持说省份/区域**（「贵州5日自驾游」→ 自动解析为受支持目的地组合）；解析不出目的地时返回 400 并给出最接近的受支持替代；`fresh=1` 跳缓存 |
| `/api/progress` | GET | 规划进度轮询（五段式：解析需求/经验提案/落地匹配/求解排程/生成文案；多城联游额外回传 `seg={i,n,city}`，前端显示「第 i/n 段 · 城市」）；`stage` 尾缀 `:r2` 表示闭环质量重算第 2 轮 |
| `/api/replace` | POST | 反馈换点：同主题邻近换点并重排当天时间轴 |
| `/api/route` | GET | 高德路径规划代理：`mode=riding\|walking\|driving&o=lng,lat&d=lng,lat`（磁盘缓存；`driving` 用于城际转移腿） |
| `/api/photo` | GET | POI 实拍图（缓存 1198 条，31 城 98.4%，缺失回退瓦片） |
| `/api/share` | POST / GET | 行程快照保存 / 读取（`GET /api/share/<id>`） |
| `/api/stats` | GET | 调用量/延迟/补位命中率统计 |

> ⚠️ 行程响应中 `result.itinerary.days[].timeline[]` 的元素字段为 `type`（`poi`/`hop`/`meal`/`hotel`/`transfer`）/ `id` / `name` / `start` / `end`，**不是** `kind` / `poi_id`；`city_meta` 不下发 open/close/rating。多城联游时 `hotel` 只在住宿城那几天出现（出发/返回行），路线绘制以「该天时间轴是否含 `hotel` 行」为判据。
>
> `transfer`（城际转移段）额外带 `min` / `km` / `from` / `to` / `source` / `leg` / `n_legs` / `mode`，`night=true` 表示夜间转移（挂在出发城当天末尾）。**`mode` 为 `driving`/`rail`/`flight`，用户未指定交通方式时为 `null`**（转移行名称也随之变成「X → Y（城际交通待定）」，不假定自驾）。整天为转移日时 `days[].transfer_day=true`；抵达日被车程顺延时 `days[].arrive_transfer=true`。

### 缺陷台账

**已修复**

- ✅ `toptw.py` depot 换位失效（M14 / `0457603`）——元组赋值 + `list.index(obj)` 双重陷阱致交换被整体撤销；换位提前到 `RoutingIndexManager` 构造**之前** + 基于 id 的下标（守卫 `test_depot_anchor.py`）
- ✅ `family_ok=false` 仅在离线链路生效（M14 / `0457603`）——判据下沉 `sequencer.is_family_query` + `poi_db.is_family_ok`，确定性 gate 挂六个入口（守卫 `test_family_gate.py`）
- ✅ 日内空档（M15 / `d25119e`）——≥45min 空档逐条核对后**全部出现在正餐点之前**（餐厅被钉在 12:00/18:00 整点）；`MEAL_EARLY_TOL_H=1.0` + 等待段补餐 + `scan_gaps` 分类披露，同扫描 357min → 60min（守卫 `test_gap_manage.py`）
- ✅ **未指定交通方式却假定跨城自驾**（2026-09-21 / 报障）——「苏杭3天联游」里凭空出现「自驾 苏州 → 杭州」转移行与「从 苏州 驾车到 杭州」通知（自驾主题其实并未触发，只是文案无条件写了自驾）。修＝`intercity_mode(query)` 只认明说的方式，未指定则转移行写「（城际交通待定）」、`mode=null`、通知披露「时长按驾车口径估算」，并可据此填补高铁/飞机（守卫 `test_intercity_mode.py`）
- ✅ **多城联游进度条停在「解析需求」**（2026-09-21 / 报障）——单城路径用 `_plan_extra_kw` 透传 `progress`（两处），而**多城 `plan_multi` 根本没接 progress**、段内 `planner.plan()` 也没传 → `/api/progress` 永远只拿到第一行的 `parse`。修＝`plan_multi(..., progress=)` 逐段包装后透传，并回传 `seg={i,n,city}` 让前端显示「第 i/n 段 · 城市」（否则进度条会在每城的 proposal→regen 之间来回跳，看不出整体进度）（守卫 `test_multicity_progress.py`）
- ✅ **提了地名却静默按默认城市规划**（M20 / PR #4）——「川西4日游」「江南水乡5日游」被排成上海，且响应标 `from_query=true`（谎称城市来自需求）。根因：目的地解析只有「命中白名单」与「回落 `DEFAULT_CITY`」两个出口；护栏仅在 LLM 填了 `city_raw` 时生效。修＝解析层 + 「提了地名但解析不出 → 明确报错并给替代建议」（守卫 `test_destination_resolve.py`）
- ✅ 点名／远郊点「能排但不被提案」（M15 / `d25119e`）——三层修复：确定性注入 → 必选与对账口径（`named_pois`）→ 目的地型餐饮豁免（守卫 `test_named_inject.py`）
- ✅ **点名点被修复链丢弃**（M19 / PR #3）——query「织金洞1日游」最终行程里没有织金洞。根因**不在求解器**（spy 包住 `toptw.solve_day` 实测 `forced` 已把它保留），而在 `order_day._greedy` 选点**不看闭园时间** → 一级修复（违规触发的贪婪重排）把它抛到 14:17 到达 → 二级修复 `_repair_by_drop` **不问它是不是用户点名的**直接剔（求解器算不出 14:17：它按 `SetRange(lo, close−dur)` 硬约束到 ≤14:00，差额正是排序器插入的**餐块**）。修＝`required` 从 `compose` 透传到修复链 + 注入位置按窗口分流（真夜间点队尾、其余队首）。实测 3/10 → **0/10**（守卫 `test_named_guard_and_merge.py`，含不传 `required` 必被剔的对照）
- ✅ 近邻目的地跨城重复游玩 + `_alloc_notice` 死代码（M19 / PR #3）——允许 POI 重叠的代价：万峰林的招牌点同时也是兴义的（前缀 `XY`/`WF`），「兴义万峰林3日游」把同一片景区走两遍（修＝`merge_near_destinations`，阈值 25km，排在 `allocate_city_days` **之前**）；`_alloc_notice` 只有构建、没有消费点，`city_days_adjusted`（「你要求苏州 2 天，实际安排 1 天」）**从未到达用户**（修＝并入 `merged_notices`）（守卫 `test_named_guard_and_merge.py`）
- ✅ 19:00 后开门的点结构性不可排（M15 / `d25119e`）——`LATE_POINT_MARGIN_MIN=60` 按池内最晚需求放宽求解预算（上限真实日窗）
- ✅ 聚合层丢字段：多城联游时住宿锚点在前端完全不可见（M15 / `007a1e8`，报障 18）——`plan_multi` 自建结果字典漏透出单城 `plan()` 的 `hotel`/`notices`，叠加「时间轴不显示酒店名」与「恢复字段后 `drawRealRoutes` 又给非住宿城补酒店腿」；修＝透出 `hotel` + 时间轴插 `type=hotel` 出发/返回行 + 路线判据改「该天是否含 hotel 行」+ `_lift_seg_notices` 按偏移重写分段 Day 号（守卫 `test_multi_hotel.py`）

**遗留（主动不修）**

- 亲子约束只到「点级」——能拦掉不适宜点位，但没有时段级节奏保障（如「上午户外、下午室内」的带娃节律）
- TOPTW 不惩罚行程内部空档——2026-09-17 实测确认这是**有意为之**：给时间维度加「总跨度代价」压不掉结构性空档（要排 19:00 的点就必然跨到 21:30），却会实实在在吃掉 POI（广州空档不变、苏州 6→5、系数调到 5 时崩到 1 点）。空档改为**披露**（`_gap_notices` 逐日告知时长与成因）
- 多城联游只有**单城**住宿锚点——`_hotel_city_probe` 只解析酒店归属的那一座城（住宿城天数 +1），非住宿城那几天没有落脚锚点（如苏杭联游的苏州天）；要支持「每城一个锚点」需扩展为多城解析
